# 환승 경로 검색

기존에는 `TagoTimetable.search`가 출발·도착역 한 쌍만 조회하고 `CallSession._find_trains`가 `choose_train`으로 한 열차를 골랐다. 직통편이 없으면 `NO_SEATS_THAT_DAY`로 응답했고, TAGO 오류는 `RailRouter.search`가 임의의 모의 시간표로 바꿨다. TAGO 열차도 `seats_available=True`였으므로 운행 정보, 좌석 재고, 조회 오류가 구분되지 않았다.

공공데이터포털 [TAGO 열차정보 명세](https://www.data.go.kr/data/15098552/openapi.do)에 있는 기능과 기존 구현을 기준으로 한다. `GetCtyCodeList` → `GetCtyAcctoTrainSttnList`로 역 이름과 ID를 얻고 `GetStrtpntAlocFndTrainInfo`에 `depPlaceId`, `arrPlaceId`, `depPlandTime`을 보낸다. 출발역과 도착역 ID는 모두 필수다. 이 API의 역 목록은 노선 연결 그래프가 아니며, 좌석 재고·예약·발권 기능도 없다. 별도의 미확인 노선 API나 출발역 전체 운행 조회 기능을 가정하지 않았다.

## 환승역 고르기 (전체 시간표)

TAGO는 역 한 쌍씩만 답하고 초당 요청 한도가 있어서, 전국 역을 차례로 물으면 몇 초 만에 막힌다. 그래서 환승역은 [한국철도공사 열차운행정보](https://www.data.go.kr/data/15125762/openapi.do)로 고른다.

1. 하루치 모든 여객열차의 정차역과 시각을 받아 `server/.cache/korail_runs`에 저장한다. 운행정보는 어제까지만 있어서 앞날은 지난주 같은 요일 시간표를 쓴다. 서버가 켜질 때 앞으로 7일 치를 미리 읽는다.
2. 그 시간표에서 Connection Scan으로 한 번 갈아타는 가장 빠른 경로를 계산하고, 갈아타는 역 상위 3곳만 아래 TAGO 검증에 넘긴다(`KorailRuns.hubs`).
3. TAGO는 그 역들에 대해서만 실제 시각과 운임을 확인한다. 대전→강릉 기준 TAGO 요청은 125번에서 5번으로 줄었다.
4. 여러 경로 중에서는 직통과 같은 기준으로 원하는 시각에 가까운 것을 고르되, 승강장에서 기다리는 시간은 1분을 1분으로 센다(`choose_route`).
5. TAGO가 막히거나 실패하면 운영 서버는 예비 시간표로 통화를 이어 간다.

## 검색과 호출 범위

1. 기존 AUTO 작업자 또는 TAGO로 직통편을 조회한다. 기존 시간대·시간 근접도·승차시간 가중치·알려진 매진편 대안 정책을 유지한다. 조건에 맞는 직통편이 있으면 추가 환승 조회 없이 추천한다.
2. 적절한 직통편이 없거나 AI 도구에 `include_transfers=true` 또는 `prefer_transfer=true`가 전달되면 환승을 조회한다. 기본 출발·도착역 지원 범위는 기존 음성 도구의 24개 역 그대로다. 환승역은 위 "환승역 고르기"대로 코레일 전체 시간표가 고른 빠른 환승역 세 곳만 TAGO로 확인한다.
3. 유효한 첫 구간이 있는 역만 두 번째 구간을 조회한다. 첫 구간 도착 일시 + 최소·최대 대기시간에서 날짜를 계산한다. 자정을 넘으면 다음 출발일의 시간표도 조회하며, 도착 일시를 임의로 하루 더해 보정하지 않는다. 역 이름이 같은 곳에서만 환승하고 동일 열차번호의 두 구간은 환승으로 만들지 않는다.
4. 두 구간의 양수 운행시간과 실제 일시 순서, 출발 시간대, 예약 준비시간, 최소·최대 대기를 검증한다. 구간 키의 조합으로 중복을 제거한다. 두 번째 구간은 출발시간 정렬과 이진 탐색으로 연결 가능한 시간 범위만 조합한다.
5. 직통을 앞에 유지하고 환승은 전체 소요시간, 최종 도착 일시, 안정적인 키 순으로 정렬한다. 기본 추천은 기존 직통 정책을 따르며, 환승을 명시적으로 선택하면 `prefer_transfer=true`로 새 전체 여정을 제안하고 다시 동의를 받는다. 앞·뒤 열차 요청도 전체 환승 여정으로 다시 검색한다.

환경 설정은 `.env.example`에 있다.

| 설정 | 기본값 | 의미 |
| --- | --- | --- |
| `TRANSFER_MIN_MINUTES` | 20 | 같은 역에서 필요한 최소 환승 대기 분 |
| `TRANSFER_MAX_MINUTES` | 180 | 최대 환승 대기 분 |
| `TRANSFER_MAX_QUERIES` | 600 | 환승 검색 한 번의 구간·날짜 조회 상한 |
| `TRANSFER_TIMEOUT_SECONDS` | 20 | 환승 탐색 전체 제한 초 |

탐색 작업과 TAGO HTTP 요청은 각각 동시 8개로 제한한다. 동일 구간·날짜 시간표는 60초 캐시하고 최대 2,048개를 보관한다. 역 디렉터리는 기존 디스크 캐시를 사용한다. API 응답은 페이지당 최대 500개(도시 목록 100개), 최대 8페이지를 확인하며 페이지 누락을 빈 결과로 취급하지 않는다. 600은 HTTP 요청 수가 아니라 캐시 조회를 포함한 **구간·날짜 조회 수**다. 최초 직통 조회와 역 목록 조회는 별도이며, 구간 조회당 HTTP 요청은 최대 8회다. 연속 세 번 오류가 발생하면 남은 후보 탐색을 중단한다. 실제 API 할당량에 맞게 상한과 제한시간을 낮출 수 있다.

시간 또는 호출 예산에 도달하면 검색 완료로 표시하지 않는다. 일부 후보 API 오류가 있어도 이미 검증한 경로는 반환한다. 운영 서버는 TAGO 직통 조회가 실패하면 예비 시간표로 통화를 이어 가고(`sample_on_failure`), 이때 환승은 찾지 않는다. 콘솔의 열차 출처(railSource)가 mock으로 남는다.

## 데이터와 음성 동의

`Itinerary`는 한 개 또는 두 개의 `Train`을 담는다. `Choice`, `Proposal`, `Hold`에 선택적으로 붙여 기존 단일 열차 필드와 직통 경로를 유지했다. JSON의 `itinerary`에는 `kind`, `legs`, `transferCount`, `transferStation`, `waitMinutes`, `durationMinutes`, `fare`, `seatAvailability`가 있다. `fare`는 구간별 성인 운임 합계이며 한 구간이라도 운임이 없으면 null이다. 제안 `train.fareTotal`은 기존 인원·경로 할인 정책을 **각 구간의 출발일 기준으로 각각** 적용한 예상 총액이며 운임 미확인일 때 null이다. 실운임 재확정 기능은 없다.

TAGO의 `seatsAvailable`은 null이며 ‘좌석 미확인’이다. 알려진 매진(false)과 구분하여 시간표 제안에는 사용할 수 있지만 재고나 발권을 약속하지 않는다. `find_trains`는 `direct_found`, `transfer_found`, `no_route`, `api_error`, `search_incomplete` 상태를 반환한다. `direct_found` 불리언은 직통 운행 조회 여부이며 재고를 뜻하지 않는다. `say`, `say_short`, `facts`, `alternatives`에 결과와 전체 여정을 전달한다. ‘직통 미조회’를 ‘기차표 없음’이나 ‘매진’으로 읽지 않는다. 새로운 검색이 시작되면 이전 제안과 보류한 경로 우대 질문을 무효화한다.

환승 제안은 짧게 말한다. "바로 가는 기차가 없어요. ○○에서 한 번 갈아타요. 출발, 도착, 모두 걸리는 시간, 요금이에요. 예약할까요?" 열차 번호, 구간별 시각, 기다리는 시간은 물어볼 때 facts로 답하고 문자에 적는다. 재확인은 "○○에서 한 번 갈아타서 ○시에 도착하는 기차예요. 예약할까요?"이고, 청취 완료·동의 판정·유효기간·스위치 게이트는 직통과 같다.

## 모의 예약과 호환성

환승은 AUTO/ASSIST 모드에서도 **모의 예약만** 지원한다. `hold_route`가 각 구간에 별도 Hold를 만들며 중간 실패·취소 시 이미 생성한 구간을 해제한다. 합산 Hold는 여정 묶음이지 단일 승차권이 아니다. 기존 BookingRecord에 `extra.itinerary`, `extra.legHolds`를 저장하므로 Firestore 마이그레이션은 필요 없다. 한 건의 모의 결제에 예상 합계를 전달하고 문자에는 각 구간의 예약번호·좌석·운임을 따로 적는다. 취소·결제 시간 초과·미결제 통화 종료는 여정의 각 Hold를 해제한다. 직통 AUTO/ASSIST 예약 경로는 유지한다.

운영 콘솔은 기존 열차 카드로 각 구간과 날짜, 대기·전체 시간, 구간별 모의 예약번호를 표시한다. `/console/calls/transfer?demo=1`은 화면 검토용 가상 시간표이며 실제 운행을 증명하지 않는다. `node tools/capture-screens.mjs --transfer-only`로 밝은/어두운 테마와 데스크톱/모바일 캡처를 만들 수 있다.

## 검증과 남은 제약

`server/tests/test_itineraries.py`는 외부 네트워크 없이 시간표 fixture와 `httpx.MockTransport`를 사용한다. 정상 직통, 환승, 역순·짧은·긴 대기, 허용 경계, 다음 날 출발·도착, 경로 없음, API 오류, 중복, 정렬, 호출 예산·기한, 기존 직통 추천, 전체 여정 동의와 모의 예약·합산 결제·문자, 부분 예약 실패 시 해제, TAGO 페이지·캐시·좌석 미확인을 검증한다. README의 ruff, mypy, pytest, TypeScript 검사와 build를 실행한다.

2026-11-13 처음 검증 때는 pytest 59개였고, 지금은 `server/tests` 전체를 돌린다(ruff, mypy, pytest, 두 앱 타입 검사와 빌드).

1회 환승, 같은 역 환승만 지원한다. 서울↔청량리처럼 역간 이동, 환승 2회 이상, 실제 좌석 확보·실결제·실제 연결 승차권, 모든 후보를 끝까지 검색했다는 보장은 제공하지 않는다. 최소 20분은 조정 가능한 기본값이며 모든 이용자·플랫폼의 이동 가능성을 보장하는 값은 아니다. 실제 TAGO 키로 전국 구간의 실응답 검증은 이 작업에서 실행하지 않았다.
