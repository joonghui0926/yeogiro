# 여기로 11주차 프로토타입 기획안

작성 2026-11-13 · 해커톤 당일 13:10 시작 기준

## 0. 한 줄 정의

테스터 폰에 설치한 PWA "여기로"가 삼성 전화 앱과 똑같이 보이고, 거기서 전화를 걸면 OpenAI 음성 AI가 받는다. 어르신이 한 문장으로 말하고 "응" 하면 조중휘 코레일 계정으로 실제 좌석을 잡고, 원터치 결제(가짜) 후 삼성 메시지 화면으로 확인 문자가 온다. 운영자는 콘솔에서 통화마다 자막, 도구 호출, 게이트 판정을 본다.

| 구분 | 진짜 | 가짜 |
| --- | --- | --- |
| 전화 | | 전화망. 웹 화면이 삼성 전화 앱을 재현하고 음성은 WebRTC |
| 대화 | OpenAI 음성 대화, 끼어들기, 말 바꾸기 | |
| 열차 | 코레일 실시간 조회와 실제 좌석 예약(AUTO). 막히면 공공데이터 시간표·운임 | AUTO가 막히면 잔여석과 예약번호 |
| 결제 | 동의 게이트, 결제 요청 흐름 | 원터치 결제 화면과 승인(돈은 움직이지 않음) |
| 문자 | 문자 내용과 도착 타이밍 | 삼성 메시지 화면 재현(통신망 문자 아님) |
| 기록 | 통화 기록, 측정 지표, 운영 콘솔 | |

완성 기준: 팀원 폰에서 여기로 실행 → 키패드로 번호 입력 → 통화 → 한 문장 → 실제 열차 1개 제안 → "응" → 실제 예약 생성 → 원터치 결제 → 문자 도착 → 콘솔에 통화 전체 기록. 통화가 끝나면 예약은 자동 취소된다.

## 0-1. 현재 상태 (2026-11-13)

- 배포됨: 폰 PWA·콘솔 PWA(Firebase Hosting), 통화 서버(Cloud Run 서울), Firestore 규칙·인덱스, 테스터 13명(데모 + 1~12).
- 열차 조회는 공공데이터 TAGO 실데이터(`apis.data.go.kr/1613000/TrainInfo`). 예약은 MOCK이 기본이다. 코레일 비공식 API는 로그인까지 되지만 조회부터 `MACRO ERROR`로 막혀 있어 AUTO는 쓰지 않는다. 실제 표가 필요하면 콘솔에서 ASSIST로 바꾼다.
- 검증:
  - 텍스트 시나리오 카드 9장 통과
  - 운영 주소에서 음성 통화 7건: 기본, 요금 질문, 말 바꾸기, 망설임·거절, 청력·사투리, 그리고 수정 후 재검증 2건
- 운영 데이터로 찾아 고친 것:
  - 출발 시각만 보고 4시간짜리 무궁화를 고르던 문제 → 걸리는 시간도 반영
  - 끝인사 누락 → 서버가 보장
  - 첫 방문 때 서비스워커가 페이지를 새로고침하던 문제 → 새 버전은 통화 중이 아닐 때 자동으로 적용
  - 결제 비밀번호 연타가 씹히던 문제
  - 결제까지 끝난 예약이 통화를 끊을 때 취소로 기록되던 문제
  - Cloud Run이 잠깐 두 대로 늘면 연결 신호가 다른 서버로 가서 AI가 받지 않던 문제 → 폰이 통화가 있는 서버에 닿을 때까지 다시 보냄
  - 카카오톡 안 브라우저에서 AI 목소리가 막히던 문제 → 기본 브라우저로 넘기고, 통화 버튼을 누를 때 재생을 미리 엶
  - "다음에 할게요"를 다음 기차로 알아듣던 문제 → 거절로 처리
  - 안 사겠다고 한 통화가 "중단"으로 남던 문제 → "예약 안 함" 결과 추가
- 화면 캡처는 [docs/screens](screens/README.md), 논문용 그림은 [docs/figures](figures/).
- 남은 것: 실제 갤럭시 폰으로 사람이 거는 통화 테스트(링크만 열면 됨), 고령 테스터 섭외.

## 1. 수업 프로토타입 적합성

- 확인할 질문은 그대로다. "어르신이 가족 도움 없이 통화만으로 예약 확정까지 가는가." 위험한 가정은 대화, 동의, 결제 신뢰이고 전화망은 아니다. 그래서 전화망을 가짜로, 대화와 예약을 진짜로 둔다.
- 수업 규칙(실제 결제 금지)을 지킨다. 결제는 화면과 승인 흐름만 있고, 코레일 예약은 미결제 상태로 잡았다가 취소한다.
- 제출물 "프로토타입 공개 URL" 칸에 여기로 주소를 그대로 낸다.
- 잃는 것과 보완
  - 본인 폰이 아닌 팀 폰: 결과 기록에 명시한다.
  - 브라우저 음질이 전화보다 좋음: 콘솔의 "전화 음질 모드"로 마이크를 300~3400Hz로 깎아 실제 통화 조건을 만든다. 실험은 켜고 발표는 끈다.
  - 발신번호 식별: 테스터별 설치 링크(`/t/3`)로 대신한다.

## 2. 화면

### 2.1 테스터 폰 PWA "여기로"

- 설치: 테스터 링크로 열고 홈 화면에 추가. 앱 이름 "여기로", 아이콘은 여기로 파비콘(초록 바탕 路). `display: standalone`이라 실제 안드로이드 상태바와 내비게이션 바가 그대로 보이므로 화면 안에 가짜 상태바를 그리지 않는다.
- 기준 화면: 갤럭시 One UI 8 전화 앱과 메시지 앱. 실제 기기 스크린샷을 옆에 두고 여백, 글자 크기, 버튼 위치를 픽셀 단위로 맞춘다. 삼성 전용 폰트와 아이콘 파일은 쓰지 않고 Pretendard와 직접 그린 SVG로 같은 모양을 만든다. 소리도 파일을 가져오지 않고 같은 주파수로 합성한다.
- 화면 목록
  1. 키패드: 상단 입력 숫자, 3×4 키패드(숫자 + 알파벳 보조), 초록 통화 버튼, 하단 탭 키패드·최근기록·연락처. 키를 누르면 DTMF음과 짧은 진동.
  2. 연락처: "여기로 기차예약" 한 명이 저장돼 있다. 누르면 바로 발신.
  3. 발신 중: 이름, 번호, "전화 거는 중…", 링백음.
  4. 통화 중: 이름, 경과 시간, 버튼 6개(녹음, 영상통화, 블루투스, 스피커, 음소거, 키패드), 빨간 종료 버튼. 스피커는 켜진 상태로 시작한다.
  5. 결제 알림과 결제 시트: 통화 화면 위로 헤드업 알림 → 누르면 원터치 결제 시트. 비상업 수업 프로젝트라 카카오페이 원터치의 이름과 모양을 그대로 쓰기로 했다(2026-11-13 결정). 시트에 "체험용 결제입니다"를 늘 표시하고 카드 정보는 받지 않는다. 공개 주소가 피싱으로 표시될 위험은 남아 있다.
  6. 비밀번호 패드: 6자리, 아무 숫자나 통과. 지문 버튼은 탭으로 통과.
  7. 통화 종료: "통화 종료" + 통화 시간, 종료음 후 최근기록 탭으로.
  8. 메시지: 헤드업 알림 → 누르면 삼성 메시지 대화 화면. 발신자 "여기로", 받은 말풍선, 시각. 메시지 목록 화면도 있다.

### 2.2 운영 콘솔 PWA "여기로 운영" (`/console`)

참고한 대시보드: Vapi·Retell의 통화 로그(통화별 자막과 도구 호출 타임라인), Stripe 대시보드(목록 → 상세, 넉넉한 표), Linear(조용한 색, 키보드 이동), Vercel(빈 공간으로 구획).

원칙

- 선으로 나누지 않는다. 구획은 여백(24/32/48px)과 면 색 차이로 만든다. 표도 행 사이 선 없이 행 높이 52px과 hover 면으로 구분한다.
- 한 화면에 한 가지 일. 개요, 목록, 상세, 실시간을 각각의 페이지로 둔다.
- 글자: 본문 15px, 표 15px, 보조 정보 13px가 최소. 핵심 숫자 32px, 숫자는 tabular-nums.
- 색: 따뜻한 회색 바탕, 흰 면, 강조는 로고 초록 하나. 상태 칩은 채도 낮은 3색(완료·중단·실패). 그라데이션, 이모지, 반투명 유리 효과, 모든 것을 카드로 감싸기를 하지 않는다.
- 다크 모드 지원.

페이지

1. 개요: 큰 숫자 4개(안내 없이 완주 비율, 예약당 되묻기 평균, 동의 없는 예약 수, 평균 통화 시간)와 각 목표선. 아래에 시나리오 카드 8장 진행 상태, 최근 통화 5건.
2. 통화: 표(시각, 테스터, 길이, 결과, 되묻기, 멈춘 지점, 코레일 모드). 필터는 테스터·결과·날짜만.
3. 통화 상세
   - 웹: 왼쪽은 시간순 타임라인. 발화는 화자와 시각이 붙은 문장으로 흐르고, 도구 호출은 그 사이에 들여 쓴 블록(이름, 입력, 결과, 걸린 시간; 기본 접힘). 오른쪽은 고정 요약(열차, 금액, 예약번호 가림, 게이트 8조건, 결제 상태, 되묻기·끼어들기 수, 응답 지연).
   - 모바일: 요약이 위, 아래에 탭 대화·도구·판정.
   - 녹음 동의가 있으면 상단에 재생 막대.
4. 실시간: 진행 중 통화의 자막이 흐르고, ASSIST 요청이 오면 큰 카드로 뜬다(열차 정보 복사, 예약번호 입력). 예약 킬 스위치, 코레일 모드, 전화 음질 모드 토글.
5. 테스터: 프로필(가명, 기본 출발역, 경로 여부), 설치 링크와 QR.

모바일 콘솔은 하단 탭(개요·통화·실시간·테스터), 목록 → 상세는 화면 전환으로.

## 3. 통화 파이프라인

```
테스터 폰 ──POST /api/calls──▶ 여기로 서버: 통화 문서 생성, 세션 키 발급(지시문·도구·목소리 고정)
테스터 폰 ──WebRTC(SDP)──▶ OpenAI Realtime: 음성 연결, call_id 수신
테스터 폰 ──POST /api/calls/{id}/attach──▶ 서버가 사이드밴드 WebSocket 연결
OpenAI ──사이드밴드──▶ 서버: 자막, 도구 호출, 발화 시작·끝 이벤트
서버 ──▶ Firestore: 모든 이벤트 기록, 결제 요청, 문자함, 코레일 작업
Firestore ──구독──▶ 테스터 폰(결제 시트, 문자), 운영 콘솔(실시간)
코레일 작업자(팀 노트북) ──구독──▶ Firestore 작업 큐 ──▶ 코레일
```

- 도구는 서버만 실행한다. 폰은 음성만 주고받고, 도구 호출과 결과는 사이드밴드로 서버가 처리한다. 그래서 기록을 믿을 수 있고 "AI는 말만, 실행은 게이트" 원칙이 지켜진다.
- 폰의 SDP는 서버가 받아 OpenAI에 넘긴다(`POST /v1/realtime/calls`). API 키와 지시문이 폰에 내려가지 않는다.
- 결제 시트와 문자는 서버가 SSE(`/api/calls/{id}/events`)로 폰에 바로 보낸다. 폰은 Firebase에 접근하지 않는다.
- 2026-11-13 새벽 실측: 헤드리스 브라우저에 한국어 음성 파일을 마이크로 넣어 키패드 발신부터 결제, 문자, 종료, 자동 취소까지 한 통화를 완주했다.
- 모델: `gpt-realtime-2.1` 기본. 브라우저 연결 방식이 문서화돼 있고 `semantic_vad`로 천천히 말해도 끊지 않게 할 수 있다. 1단계에서 `gpt-live-1`(목소리 noeul)의 WebRTC 지원을 확인하고 되면 같은 문장 3개로 비교한다.

### 3.1 통화 상태

```
DIALING → GREETING → LISTENING → SEARCHING → PROPOSED
PROPOSED ─동의→ HOLDING → PAYMENT_PENDING → PAID → CLOSING → ENDED
PROPOSED ─조건 변경→ SEARCHING
PROPOSED ─동의 아님→ PROPOSED(재확인, 두 번째도 아니면 열차 안내 문자를 보내고 다른 시간을 묻는다)
HOLDING ─실패→ PROPOSED(대안) 또는 CLOSING
PAYMENT_PENDING ─15초·35초 안내, 60초 무응답→ 예약 취소 → CLOSING
```

상태는 서버의 `CallSession`이 가진다. 폰의 화면 상태(발신 중, 통화 중, 종료)는 별도의 작은 상태기계다.

### 3.2 도구(AI에 노출)

| 도구 | 입력 | 결과 |
| --- | --- | --- |
| `find_trains` | 도착역, 원문 시간 표현, AI가 추정한 날짜·시간대, 인원 | 제안 1개(매진이면 대안 1개), `option_id`, 그대로 읽을 `say` |
| `request_booking` | `option_id` | 게이트 통과 시 좌석 확보 후 결제 요청을 띄우고 `say` 반환. 실패 시 이유와 다음 말 |
| `cancel_booking` | 없음 | 최근 1건 취소 |
| `end_call` | 없음 | 끝인사가 다 나간 뒤 종료 |

결제는 도구가 아니다. 결제 승인은 폰의 탭이 서버 API로 들어와서 처리되고, 서버가 대화에 "결제 완료" 사실을 넣어 AI가 안내한다. `say` 문장의 날짜·시각·금액은 코드가 만든다("오후 두 시 육 분", "만 삼천이십 원").

### 3.3 동의 게이트

`request_booking`은 아래를 모두 통과해야 코레일에 예약을 보낸다. 하나라도 실패하면 예약하지 않고 AI에 재확인을 돌려준다. 판정 결과는 통화 기록에 조건별로 남는다.

1. 이번 통화에서 서버가 만든 `option_id`이고 3분 이내
2. 그 제안 문장이 끊기지 않고 끝까지 재생됨
3. 그 뒤 어르신 발화를 별도의 확인 모델이 "명확한 동의"로 판정. 음성 모델의 판단과 독립적인 두 번째 판정이다. 키워드 목록으로 판정하지 않는다.
4. 등록된 테스터 링크에서 온 통화
5. 테스터당 하루 3건, 동시 1건 이하
6. 출발까지 20분 이상
7. 같은 열차에 잡아 둔 예약 없음
8. 예약 킬 스위치가 켜져 있음

## 4. 소리 설계

| 순간 | 설계 |
| --- | --- |
| 키 입력 | 숫자별 DTMF 두 음 합성, 120ms, 진동 15ms |
| 발신 | 한국 링백(440+480Hz, 1초 울림 2초 쉼)을 최소 한 번 끝까지. 연결 지연을 이 소리로 덮는다. 15초 안에 연결이 안 되면 "연결할 수 없습니다" |
| 연결 | 링백이 멈추는 순간 타이머 시작, 0.6초 안에 첫마디 |
| 첫마디 | "여기로 기차 예약 AI예요. 어디로, 언제 출발하세요?" (AI임을 처음에 밝힘) |
| 턴 감지 | `semantic_vad`, eagerness low. 말을 늘이거나 쉬어도 끊지 않음 |
| 끼어들기 | 어르신이 말하면 즉시 멈춤. 재생된 부분까지만 대화에 남김 |
| 잡음·에코 | 브라우저 에코 제거·잡음 억제 켬. 스피커폰 기준이라 입력 잡음 처리는 far_field |
| 기다림 | 도구를 부르기 전에 "잠시만요, 찾아볼게요." 한 번. 4초를 넘기면 8초마다 "자리 잡는 중이에요" |
| 숫자 읽기 | 코드가 만든 문장을 그대로 읽음. 시는 고유어, 분은 한자어, 금액은 만 단위 |
| 확인 문장 | 날짜·구간·출발·도착·금액 5개, 12초 이하 |
| 속도·크기 | 출력 속도 0.9(파라미터 확인 후 적용, 안 되면 지시문). 출력에 컴프레서를 걸어 작은 소리를 키움 |
| 침묵 | 7초 → "천천히 말씀하셔도 돼요." 다시 10초 → "다시 전화 주시면 도와드릴게요." 후 종료 |
| 결제 대기 | 시트가 뜰 때 알림음, AI "화면에 노란 결제 버튼이 나왔어요. 눌러 주세요." 15초와 35초에 다시 안내, 60초면 예약 취소 |
| 결제 완료 | 시트 완료음 → AI "결제됐어요. 문자로 보내드렸어요." → 2초 뒤 문자 알림음과 진동 |
| 종료 | 끝인사가 다 재생된 뒤 끊음. 종료음(480+620Hz 0.5초 간격 3회) 후 통화 종료 화면 |
| 전화 음질 모드 | 마이크를 대역 통과 300~3400Hz + 8kHz로 깎음. 콘솔에서 켜고 끔 |
| 녹음 | 테스트 전 동의한 경우만 양쪽 음성을 저장해 콘솔에서 재생 |

## 4-1. 대답 유형별 처리

어르신은 "응"만 하지 않는다. 제안 뒤 대답을 7가지로 나누고, 유형마다 AI가 할 말과 서버가 할 일을 정해 둔다. 판정은 키워드가 아니라 모델이 하고, 돈이 걸린 동의만 별도 확인 모델이 한 번 더 본다.

| 유형 | 예 | AI | 서버 |
| --- | --- | --- | --- |
| 분명한 동의 | 응, 그려 그걸로 혀, 네네 해 주세요, 좋아요 잡아 줘요 | "네." 후 예약 요청 | 확인 모델이 동의 판정, 게이트 8개 통과 시 좌석 확보 |
| 제안에 질문 | 얼마라고요?, 몇 시 도착이에요?, 무슨 기차예요? | 도구가 준 facts로 한 문장 답, "예약할까요?" | facts는 코드가 만든 읽기 문장(시각·요금·소요 시간·열차) |
| 못 들음 | 뭐라고?, 응?, 다시 한 번 | say_short("오전 아홉 시 이 분에 동대구 가는 기차예요. 예약할까요?") | "응?"은 동의로 세지 않음 |
| 잘 안 들림 | 잘 안 들려, 천천히 | 속도를 0.8로 낮추고 say_short | 세션 속도 변경 |
| 조건 변경 | 오전으로, 내일로, 수원에서 탈게, 그 앞에 차는? | "네, 다시 찾아볼게요." 후 재검색 | 앞·뒤 차는 현재 제안 기준으로 코드가 고름 |
| 거절 | 아니 됐어, 다음에 할게요 | "다른 시간으로 찾아볼까요?" 한 번만, 또 거절이면 마무리 | 예약 없음 |
| 망설임·딴 얘기 | 음… 글쎄, 우리 아들이 서울 사는데 | "네." 하고 기다리거나 하던 질문으로 돌아옴 | 7초 침묵이면 say_short, 10초 더면 정중히 종료 |

- 동의와 질문이 섞이면("응, 근데 얼마라고?") 질문에 먼저 답하고 다시 묻는다.
- 판정 대상은 제안이 시작된 뒤에 시작한 말만이다. 앞 질문의 답이 늦게 전사돼도 섞이지 않는다.
- 제안 끝("예약할까요?")에 겹쳐 "응" 하는 건 들은 것으로 본다. 그보다 앞에서 끊고 들어오면 다시 묻는다.
- 확인 모델은 어르신이 말을 마치는 순간 미리 판정을 시작한다. 예약 요청이 오면 이미 결과가 있어 기다림이 0.5초 안팎이다.
- 고정 문장은 모두 `server/src/yeogiro/calls/lines.py` 한 곳에 있다. 문장만 바꿀 때는 이 파일만 고친다.

결제 단계의 말

| 시점 | 말 |
| --- | --- |
| 좌석 확보가 2.5초 안에 끝남 | "화면에 노란 결제 버튼이 나왔어요. 눌러 주세요." (중간 안내 없이 바로) |
| 2.5초를 넘김 | "자리 잡을게요. 잠시만요." → 8초마다 "자리 잡는 중이에요." |
| 15초 동안 안 누름 | "전화기를 귀에서 떼고, 화면 아래 노란 버튼을 눌러 주세요." |
| 35초 | "노란 버튼만 누르시면 끝나요." |
| 60초 | 자리를 풀고 "결제가 안 돼서 자리는 풀어 둘게요." |
| 결제 완료 | "결제됐어요. 문자로 표 보내드렸어요. 더 필요하신 거 있으세요?" → 2초 뒤 문자 |

검증: `python -m yeogiro.sim`이 시나리오 카드(`server/scenarios/cards.json`)를 실제 음성 모델에 텍스트로 돌려 대화, 도구 호출, 게이트 판정을 출력한다. 음성 통화 없이 대화 정책을 바꿀 때마다 돌린다. 카드는 재이용 동의, 첫 이용, 매진과 말 바꾸기, 질문, 앞 차, 청력, 망설임, 딴 얘기, 결제 안 누름 9장이다.

## 5. 코레일

예약은 조중휘 계정으로 실제로 한다. 단, 지금 비공식 API가 막히는 중이라 세 모드를 두고 콘솔에서 바꾼다. 대화 쪽은 모드를 모른다.

| 모드 | 조회 | 예약 | 언제 |
| --- | --- | --- | --- |
| AUTO | 코레일 실시간(잔여석 포함) | 실제 미결제 예약, 통화 종료 후 자동 취소 | 사전 점검 통과 시 |
| ASSIST | 공공데이터 시간표·운임 | 운영자가 콘솔 요청을 보고 코레일+ 앱으로 예약, 예약번호 입력 | AUTO가 막힐 때 |
| MOCK | 공공데이터 시간표·운임 | 가짜 예약번호 | 리허설, 발표 백업 |

- 코레일 호출은 팀 노트북의 작업자가 한다. 서버는 Firestore 작업 큐에 조회·예약·취소를 넣고, 노트북이 받아 처리한다. 계정 정보가 클라우드에 올라가지 않고, 데이터센터 IP 차단도 피한다. 노트북이 꺼져 있거나 4초 안에 응답이 없으면 서버가 공공데이터로 조회하고 ASSIST 또는 MOCK로 넘긴다.
- 라이브러리는 korail2를 감싼 어댑터로 시작하고, 최근 막힘(2026-09 로그인 403 / -2000)에 대응한 포크의 수정을 반영한다.
- 사전 점검(오늘): 노트북에서 로그인 1회, 대전→서울 조회 1회. 실패하면 오늘은 ASSIST로 확정한다. 재시도 반복은 하지 않는다.
- 계정 예의: 조회 60초 캐시, 반복 조회와 빈자리 낚아채기 없음, 하루 테스트 예약 수 제한, 통화가 끝나면 즉시 취소. 미결제 예약은 원래 10분 뒤 자동 취소된다. 월~목 열차를 쓰면 혹시 결제돼도 출발 3시간 전 반환 수수료가 없다.
- 위험: 계정 이용 제한 가능성이 있다. 팀원끼리 계정 공유는 약관 위반 사유라 작업자는 조중휘 노트북에서만 돌린다.

## 6. 결제와 문자

- 결제: `Payment` 포트의 지금 구현은 `MockOneTouch`. 게이트 통과와 좌석 확보 후 결제 요청 문서를 만들고, 폰이 구독해 시트를 띄운다. 탭하면 `POST /api/payments/{id}/approve`. 나중에 토스페이먼츠 빌링키로 바꿀 때 대화와 상태기계는 그대로다.
- 문자: `Messaging` 포트의 지금 구현은 `InAppInbox`. 서버가 테스터 문자함에 문서를 넣으면 폰이 삼성 메시지 화면으로 보여 준다. 나중에 솔라피로 바꾼다.
- 문자 내용(링크 없음)

```
[여기로] 예약 확인
11월 17일(화) 대전→서울
KTX 119 14:06 출발 · 15:10 도착
3호차 7A · 13,020원
체험용 예약입니다. 결제되지 않고 곧 자동 취소됩니다.
```

## 7. 데이터(Firestore, asia-northeast3)

| 컬렉션 | 내용 |
| --- | --- |
| `testers/{id}` | 가명, 기본 출발역, 경로 여부, 설치 토큰 |
| `calls/{id}` | 테스터, 시작·끝, 모델, 코레일 모드, 상태, 결과, 되묻기·끼어들기 수, 멈춘 지점, 열차, 예약번호(가림), 결제 상태 |
| `calls/{id}/events/{seq}` | 통화 시작 기준 ms, 종류(발화·도구 호출·도구 결과·게이트·결제·코레일·시스템), 내용 |
| `payments/{id}` | 통화, 금액, 가맹점명(가짜), 상태(요청·승인·만료) |
| `inbox/{testerId}/messages/{id}` | 발신자, 본문, 시각, 읽음 |
| `railJobs/{id}` | 종류(조회·예약·취소), 입력, 상태(대기·처리중·완료·실패), 처리자(작업자·운영자), 결과 |
| `config/runtime` | 킬 스위치, 코레일 모드, 전화 음질 모드 |

- 쓰기는 서버(Admin SDK)만 한다. 폰과 콘솔은 읽기 전용이고, 콘솔의 토글만 관리자 권한으로 `config`에 쓴다.
- 폰은 Firebase에 직접 접속하지 않고 서버 API와 SSE만 쓴다. 테스터 토큰과 폰마다 만든 기기 ID로 자기 통화만 다룬다. 콘솔은 로그인 없이 익명 로그인으로 열리고(2026-11-13 결정), 주소를 아는 사람은 기록을 보고 지울 수 있다.
- 전화번호·실명은 저장하지 않는다. 코레일 회원번호는 기록에 가려서(2462••••09) 남긴다.

- 의존 방향은 `domain ← calls ← adapters ← api/worker`. `domain`은 I/O를 하지 않는다.
- 가짜와 진짜는 같은 포트의 다른 구현이다. 통화 흐름 코드에는 `if mock` 분기가 없다. 무엇을 쓸지는 `config.py`에서 한 번 조립한다. 나중에 실제 전화(SIP)를 붙일 때는 `telephony/sip`만 추가한다.
- 금액은 정수 원화, 시간은 Asia/Seoul 기준 tz-aware.
- 타입: TS strict, Python mypy strict. 린트: ESLint + Prettier, ruff.
- 테스트: `domain` 단위 테스트, 시나리오 카드 8장을 가짜 어댑터로 돌리는 통화 흐름 테스트.
- 주석은 코드만 봐서 알 수 없는 이유가 있을 때만 쓴다. 코드를 다시 말하는 주석, 구획용 배너 주석, 이모지는 넣지 않는다. 이름이 설명을 대신한다.
- 식별자와 커밋 메시지는 영어, 사용자에게 보이는 문장은 한국어.
- 비밀값은 `.env`와 Secret Manager에만. `.env`의 키 이름은 `OPENAI_API_KEY`로 통일한다.

## 9. 배포

- Firebase Hosting: `/`는 폰 앱, `/console`은 콘솔, `/api/**`는 Cloud Run으로 rewrite. 한 주소에서 다 열린다.
- Cloud Run(asia-northeast3): FastAPI 서버. 통화 동안 사이드밴드를 유지해야 하므로 CPU 상시 할당 + 최소 인스턴스 1(테스트 기간만).
- Firebase: Blaze 요금제, Firestore(서울), Authentication(구글, 커스텀 토큰).
- 코레일 작업자: 조중휘 노트북에서 `python -m yeogiro.worker`.

| 2 | 도구, 동의 게이트, 공공데이터 조회, MOCK 예약 | 대전→서울 실제 시간표로 제안, "응"에 예약번호 |

| 6 | PWA, 배포, 팀원 폰 3대 확인 | 설치 후 전체 흐름 완주 |

직접 해 주실 것

- Firebase 프로젝트 생성, Blaze 요금제, Firestore(asia-northeast3), Authentication의 구글 로그인 켜기. 프로젝트 ID를 알려 주기.
- `firebase login`, `gcloud auth login` (터미널에서 `! firebase login`)
- `.env`에 `KORAIL_ID`, `KORAIL_PW`, 공공데이터포털 TAGO 열차정보 키 `TAGO_SERVICE_KEY`
- 콘솔 허용 이메일 목록

## 11. 위험과 대비

| 위험 | 대비 |
| --- | --- |
| 코레일 로그인 차단 | ASSIST로 전환, 대화는 그대로 |
| 코레일 계정 이용 제한 | 소량, 캐시, 즉시 취소, 반복 조회 없음 |
| 브라우저 마이크 권한·자동재생 | 통화 버튼 탭으로 오디오 잠금 해제, 첫 실행 때 권한 안내 화면 |
| 스피커폰 에코로 AI가 스스로 끊김 | 에코 제거, far_field, 시나리오로 사전 확인 |
| 결제 시트로 화면 전환이 어려움 | 새 검증 질문으로 기록. 귀에서 떼고 누르기까지 걸린 시간 측정 |
| 사이드밴드 끊김 | 자동 재연결, 끊긴 동안의 이벤트는 재전송분으로 복구 |
| 공개 URL 오남용 | 테스터 토큰 없으면 통화 불가, 하루 비용 한도 |
