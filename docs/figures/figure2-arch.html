Figure 2. 시스템 아키텍처. 두 PWA(테스터·운영 콘솔)는 Firebase Hosting으로 서빙되고, 초록 경로가 음성을 나른다: 테스터 폰은 WebRTC로 OpenAI에 직접 연결되고, 여기로 서버(Cloud Run · FastAPI)가 사이드밴드 WebSocket으로 붙어 도구를 실행한다. Hosting은 정적 파일만 내려주고, 폰의 API·SSE 요청은 Cloud Run에 직접 간다. 서버는 domain ← calls ← adapters 의존 방향을 지키며, 순수 도메인 계층이 날짜·열차 선택·운임을 계산하고 외부 시스템은 모두 포트 뒤에 있다. 열차 시간표는 공공데이터 TAGO에서 실시간으로 조회한다. 모든 통화 기록은 서버가 Admin SDK로 Firestore에 쓰고, 콘솔은 보안 규칙으로 보호된 읽기 전용 접근만 한다. 실제 코레일 예약은 작업 큐(railJobs)를 통해 조중휘 노트북의 작업자가 처리하여, 계정 자격 증명이 신뢰 경계 밖으로 나가지 않는다.
